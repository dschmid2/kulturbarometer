# Requirements Document

## Introduction

Das Kulturbarometer ist eine Webapplikation zur Untersuchung der Unternehmenskultur. Im Zentrum steht eine strukturierte Umfrage, mit der erfasst wird, wie stark die definierten Unternehmenswerte im täglichen Arbeitsalltag (Daily Business) tatsächlich gelebt werden. Die Umfrage erhebt ausschließlich den gelebten Ist-Zustand. Der angestrebte Zustand (Soll) wird nicht abgefragt, sondern ergibt sich aus der Beschreibung und den Fokussätzen der Unternehmenswerte, die beschreiben, wie sich ein gelebter Wert im Daily Business zeigen soll.

Administratoren definieren Unternehmenswerte mit Namen, Beschreibung und einem oder mehreren Fokussätzen. Aus diesen Vorgaben können Umfrage-Items in Form von Fragen oder beschriebenen Situationen (Use-Cases) auf zwei Wegen entstehen: Entweder erzeugt und verfeinert das System sie KI-gestützt über einen API-Zugang zu einer KI, oder Administratoren exportieren die Datenstruktur, erstellen die Items in einer externen KI oder einem anderen Hilfsmittel und importieren sie anschließend. In beiden Fällen entstehen Items zunächst im Status "zur Prüfung". Administratoren prüfen, bearbeiten, verfeinern, geben frei oder verwerfen sie; nur freigegebene Items werden in Kampagnen und Umfragen verwendet. Wird während einer laufenden Kampagne festgestellt, dass ein Item missverstanden wird, kann der Administrator dieses Item für die Kampagne deaktivieren, um eine schlechte Umfragequalität zu verhindern; die deaktivierte Item-Version kann anschließend unverändert für spätere Kampagnen erneut freigegeben oder zu einer neuen Item-Version überarbeitet werden. Jedes Item trägt mit einer prozentualen Gewichtung zu einem oder mehreren Unternehmenswerten bei.

Damit eine Umfrage wiederholbar und die Ergebnisse mehrerer Kampagnen vergleichbar bleiben, werden Items versioniert: Sobald eine Item-Version in einer aktivierten Kampagne verwendet wurde, ist sie unveränderlich. Jede Änderung an einem verwendeten Item, sei sie manuell oder KI-gestützt, erzeugt eine neue Item-Version im Status "zur Prüfung", die wie ein neues Item behandelt wird und die vorherige Version unverändert lässt. So kann später eine neue Kampagne auf derselben Fragenbasis gestartet werden, deren Ergebnisse mit der früheren Kampagne vergleichbar sind.

Jedes Item trägt genau eine Perspektive, die in seiner Formulierung ausgedrückt wird. Es gibt drei Perspektiven: Selbst ("Wie lebe ich den Wert persönlich?", z. B. "Ich halte zugesagte Termine ein"), Team ("Wie wird der Wert im Team gelebt?", z. B. "In meinem Team werden zugesagte Termine eingehalten") und Führung ("Wie lebt die Führung den Wert?", z. B. "Die Führung hält zugesagte Termine ein"). Dadurch erfasst die Umfrage, wie ein Unternehmenswert aus drei Blickrichtungen gelebt wird, ohne dass ein Teilnehmer dasselbe Item mehrfach bewerten muss.

Teilnehmer beantworten die Umfrage anonym. Je Item geben Teilnehmer über einen Schieberegler genau eine stufenlose Ist-Bewertung auf einer Skala von 1,00 bis 5,00 ab und können optional einen Freitextkommentar je Item hinterlassen. Die Perspektive eines Items ergibt sich aus seiner Formulierung und wird dem Teilnehmer als Kontext des Item-Textes dargestellt. Das System konsolidiert die Bewertungen je Unternehmenswert und je Perspektive zu einem gewichteten Ist-Score, sodass jeder Unternehmenswert bis zu drei Ist-Scores aufweist (einen je Perspektive). Eine Kampagne besteht aus einem Set von Fragen und Situationen/Use-Cases (Items), die abgefragt werden; über deren Werte-Zuordnungen ist die Kampagne mit den Unternehmenswerten verknüpft. Kampagnen sind Erhebungsfenster ohne festen Zielwert; das System verfolgt die Entwicklung des Ist-Scores jedes Unternehmenswerts je Perspektive über mehrere Kampagnen hinweg, sodass Administratoren erkennen, ob sich ein Wert über die Zeit verbessert oder verschlechtert. Bereits während einer laufenden Kampagne steht eine Zwischenauswertung zur Verfügung. Zum Schutz der Anonymität zeigt das System Ergebnisse erst an, wenn eine je Kampagne festgelegte Anonymitätsschwelle an Antworten erreicht ist.

## Glossary

- **Kulturbarometer**: Die Gesamtheit der Webapplikation zur Untersuchung der Unternehmenskultur.
- **System**: Die serverseitige Logik des Kulturbarometers, die Anfragen verarbeitet und Daten speichert.
- **Administrator**: Eine authentifizierte Person mit Rechten zum Verwalten von Unternehmenswerten, Items, Kampagnen und zur Einsicht in Auswertungen.
- **Teilnehmer**: Eine Person, die über den öffentlichen Kampagnen-Link oder über einen individuellen Einmal-Link anonym an der Umfrage einer Kampagne teilnimmt.
- **Unternehmenswert**: Ein von einem Administrator definiertes Kulturmerkmal (z. B. "Vertrauen"), das aus einem Namen, einer Beschreibung und einem oder mehreren Fokussätzen besteht.
- **Fokussatz**: Ein einem Unternehmenswert zugeordneter Satz, der beschreibt, wie sich der gelebte Unternehmenswert im Daily Business zeigt. Fokussätze dienen zusammen mit Name und Beschreibung als Vorgabe für die KI-gestützte Item-Generierung.
- **Item-Status**: Der Lebenszyklus-Status eines Items. Es gibt drei Werte: "zur Prüfung" (Vorschlag, noch nicht verwendbar), "freigegeben" (für Kampagnen-Pools und Umfragen verwendbar) und "deaktiviert" (nicht mehr verwendbar; eine unverändert gebliebene Item-Version kann erneut freigegeben werden, eine überarbeitete Fassung entsteht bei einer verwendeten Item-Version als neue Item-Version). Der Item-Status gehört zu einer Item-Version; eine Statusänderung verändert nie den Inhalt der Item-Version.
- **Freigabe**: Die Entscheidung eines Administrators, eine Item-Version vom Status "zur Prüfung" oder "deaktiviert" in den Status "freigegeben" zu überführen. Nur freigegebene Item-Versionen können einem Kampagnen-Pool zugeordnet und in Umfragen verwendet werden. Die erneute Freigabe einer verwendeten, deaktivierten Item-Version ändert ausschließlich den Item-Status.
- **Verfeinerung**: Die KI-gestützte Überarbeitung eines generierten oder bestehenden Items, optional anhand eines Anweisungstexts des Administrators. Bei einer nicht verwendeten Item-Version im Status "zur Prüfung" oder "deaktiviert" überarbeitet die Verfeinerung die Item-Version selbst; bei einer verwendeten Item-Version entsteht eine neue Item-Version und die ursprüngliche bleibt unverändert. Das Ergebnis ist in beiden Fällen ein Vorschlag im Status "zur Prüfung".
- **Deaktivierung**: Das Außerkraftsetzen einer Item-Version. Die Deaktivierung ändert ausschließlich den Item-Status, nie den Inhalt der Item-Version. Die Deaktivierung in einer laufenden Kampagne kennzeichnet das Item im Kampagnen-Snapshot als deaktiviert, schließt es von neuen Teilnehmer-Teilmengen sowie von Ist-Score, Auswertung und Export dieser Kampagne aus und setzt den Item-Status auf "deaktiviert". Aktiv ist ein Item, das im Kampagnen-Snapshot nicht deaktiviert ist.
- **Item-Export**: Die vom System erzeugte JSON-Datei mit allen Unternehmenswerten (Name, Beschreibung, Fokussätze) und einer Schemabeschreibung für die externe Item-Erstellung.
- **Item-Import**: Das Einlesen einer JSON-Datei mit extern erstellten Items, aus der gültige Items im Status "zur Prüfung" angelegt werden.
- **Item**: Ein von Teilnehmern zu bewertendes Umfrageelement, das als Frage oder als Situation/Use-Case ausgeprägt ist, genau einer Perspektive (Selbst, Team oder Führung) zugeordnet ist und über eine oder mehrere gewichtete Zuordnungen zu Unternehmenswerten verfügt. Die Perspektive eines Items ist in seiner Formulierung ausgedrückt. Jedes Item existiert als eine oder mehrere Item-Versionen; jede Item-Version besitzt einen Item-Status.
- **Item-Version**: Ein bestimmter Stand eines Items (Item-Text, Item-Typ, Perspektive, Werte-Zuordnungen und Gewichtungen) mit eigener Versionsnummer und eigenem Item-Status. Eine neue Item-Version wird für Kampagnen und Ist-Score wie ein neues Item behandelt. Die vorherige Item-Version bleibt unverändert bestehen und, sofern "freigegeben", für neue Kampagnen-Pools verwendbar.
- **Item-Familie**: Die Gesamtheit aller Item-Versionen, die auseinander hervorgegangen sind und über aufsteigende Versionsnummern miteinander verknüpft sind. Die Versionshistorie einer Item-Familie listet alle ihre Item-Versionen mit Versionsnummer, Item-Status und Kennzeichnung als verwendet.
- **Verwendetes Item**: Eine Item-Version, die Teil mindestens eines Kampagnen-Snapshots ist, also in einer Kampagne enthalten ist, die aktiviert wurde (Status "Aktiv" oder "Abgeschlossen"). Die Zugehörigkeit zum Kampagnen-Pool einer Kampagne im Status "Entwurf" macht eine Item-Version nicht zu einem verwendeten Item. Eine verwendete Item-Version ist unveränderlich und kann nicht gelöscht werden.
- **Frage**: Eine Ausprägung eines Items in Form einer Umfrageaussage, die von Teilnehmern bewertet wird.
- **Situation/Use-Case**: Eine Ausprägung eines Items in Form einer beschriebenen Arbeitssituation, zu der Teilnehmer angeben, wie stark sie im Daily Business zutrifft.
- **Werte-Zuordnung**: Die Zuordnung eines Items zu einem Unternehmenswert zusammen mit einer Gewichtung. Das System schlägt bei der Item-Generierung Werte-Zuordnungen vor; der Administrator kann diese Vorschläge ändern.
- **Gewichtung**: Der einer Item-Werte-Zuordnung zugeordnete Prozentsatz von 0 % bis 100 %, der angibt, wie stark ein Item zum Ist-Score eines Unternehmenswerts beiträgt.
- **Perspektive**: Eine der drei Sichten Selbst ("Wie lebe ich den Wert persönlich?"), Team ("Wie wird der Wert im Team gelebt?") und Führung ("Wie lebt die Führung den Wert?"). Jedes Item gehört zu genau einer Perspektive, die in der Formulierung des Items ausgedrückt wird. Gleichbedeutend mit "Sicht".
- **Ist-Bewertung**: Die von einem Teilnehmer über einen Schieberegler je Item einmalig abgegebene Einschätzung, wie stark das Item im Daily Business zutrifft bzw. gelebt wird, als stufenloser Dezimalwert auf der Skala von 1,00 bis 5,00. Je Item gibt ein Teilnehmer genau eine Ist-Bewertung ab; die Perspektive ergibt sich aus der Formulierung des Items.
- **Schieberegler**: Das Eingabeelement, mit dem Teilnehmer die eine Ist-Bewertung eines Items als stufenlosen Wert (Zwischenwerte zulässig, z. B. 3,70) auf der Skala von 1,00 bis 5,00 abgeben.
- **Ist-Score**: Der je Unternehmenswert und je Perspektive (Selbst, Team, Führung) berechnete gewichtete Mittelwert der Ist-Bewertungen, der ausschließlich aus den Items der jeweiligen Perspektive aggregiert wird, ausgedrückt auf der Skala von 1,00 bis 5,00 und gerundet auf zwei Nachkommastellen. Je Unternehmenswert bestehen somit bis zu drei Ist-Scores, einer je Perspektive.
- **Freitextkommentar**: Eine optionale, anonyme textliche Ergänzung, die ein Teilnehmer je Item zusätzlich zur Ist-Bewertung abgeben kann.
- **Kampagne**: Ein Erhebungsfenster mit einem definierten Kampagnen-Pool aus Fragen und Situationen/Use-Cases, einer Anonymitätsschwelle und einem bei Kampagnenstart eingefrorenen Stand der Item-Werte-Zuordnungen und Gewichtungen, ohne festen Zielwert. Die Unternehmenswerte einer Kampagne werden nicht separat zugeordnet, sondern ergeben sich aus den Werte-Zuordnungen der Items ihres Kampagnen-Pools.
- **Erhebungsfenster**: Der durch eine Kampagne festgelegte Zeitraum, in dem Teilnehmer die Umfrage beantworten.
- **Kampagnen-Pool**: Der bei Kampagnenstart festgelegte und anschließend eingefrorene Satz an Items (Fragen und Situationen/Use-Cases), aus dem die Umfrage einer Kampagne gespeist wird. Der Kampagnen-Pool besteht ausschließlich aus freigegebenen Items. Die Unternehmenswerte der Kampagne sind diejenigen Unternehmenswerte, denen mindestens ein Item des Kampagnen-Pools mit einer Gewichtung größer als 0 % zugeordnet ist. Der Kampagnen-Pool und die zugehörigen Item-Werte-Zuordnungen samt Gewichtungen (Kampagnen-Snapshot) sind nach dem Start der Kampagne unveränderlich; ausgenommen ist die Deaktivierung einzelner Items.
- **Kampagnen-Snapshot**: Der bei Kampagnenstart eingefrorene Stand des Kampagnen-Pools einschließlich Item-Text, Item-Typ und Perspektive jedes Items sowie der Item-Werte-Zuordnungen und ihrer Gewichtungen. Der Kampagnen-Snapshot bleibt für eine Kampagne im Status "Aktiv" oder "Abgeschlossen" unveränderlich; einzige zulässige Änderung ist die Kennzeichnung einzelner Items als deaktiviert (das Item bleibt im Kampagnen-Snapshot erhalten). Änderungen an einem verwendeten Item, einschließlich seiner Zuordnungen oder Gewichtungen, werden nur durch eine neue Item-Version in einer neu erstellten Kampagne wirksam.
- **Item-Anzahl je Teilnehmer**: Die bei Kampagnenstart festgelegte feste Anzahl an Items, die jeder Teilnehmer dieser Kampagne zur Bewertung erhält; eine ganze Zahl zwischen 1 und der Größe des Kampagnen-Pools.
- **Teilnehmer-Teilmenge**: Die zufällig aus den aktiven Items des Kampagnen-Pools gezogene Auswahl an Items im Umfang der Item-Anzahl je Teilnehmer, die einem einzelnen Teilnehmer beim ersten Öffnen der Umfrage zugewiesen wird. Sie wird serverseitig an den Einmal-Token bzw. die Teilnahmekennung gebunden und bei jedem erneuten Öffnen bis zur erfolgreichen Übermittlung unverändert wieder verwendet.
- **Verteilmodus**: Die bei einer Kampagne gewählte Art der Umfrageverteilung. Je Kampagne wird genau einer von zwei Verteilmodi gewählt: öffentlicher Kampagnen-Link oder individuelle Einmal-Links per E-Mail.
- **Kampagnen-Link**: Ein öffentlicher, teilbarer Zugangslink zu genau einer Kampagne, über den Teilnehmer im Verteilmodus "öffentlicher Kampagnen-Link" anonym an der Umfrage teilnehmen. Je Kampagne ist höchstens ein Kampagnen-Link gültig; der Administrator kann ihn durch einen neuen ersetzen, wodurch der bisherige sofort ungültig wird.
- **Einmal-Link**: Ein im Verteilmodus "individuelle Einmal-Links per E-Mail" erzeugter, individueller Zugangslink, der über einen Einmal-Token genau einer Kampagne zugeordnet ist. Er kann bis zur erfolgreichen Übermittlung der Umfrage beliebig oft geöffnet werden und gilt erst mit der erfolgreichen Übermittlung als verbraucht; danach ermöglicht er keine weitere Teilnahme.
- **Einmal-Token**: Ein anonymer Token, der je individuellem Einmal-Link dauerhaft gespeichert wird und genau eine erfolgreiche Übermittlung erlaubt. Der Einmal-Token enthält keine Zuordnung zu einer E-Mail-Adresse; es wird keine E-Mail-Adresse gespeichert. Eine gespeicherte Antwort enthält keinen Verweis auf den Einmal-Token, über den sie abgegeben wurde.
- **Teilnahmekennung**: Eine anonyme, im Browser des Teilnehmers gespeicherte Kombination aus einem Cookie und einem lokal erzeugten Code (z. B. im Local Storage des Browsers), mit der das System im Verteilmodus "öffentlicher Kampagnen-Link" eine wiederkehrende Browser-Teilnahme erkennt, um eine Mehrfachteilnahme desselben Browsers an derselben Kampagne zu verhindern. Die Teilnahmekennung enthält keine personenbezogenen Identifikationsdaten und wird nicht aus solchen abgeleitet.
- **Zwischenstand**: Die von einem Teilnehmer vor der Übermittlung bereits erfassten Ist-Bewertungen und Freitextkommentare. Der Zwischenstand wird ausschließlich im Browser des Teilnehmers gespeichert, nie auf dem Server.
- **Serverseitige Heuristik**: Ein serverseitiger, anonymer Mechanismus im Verteilmodus "öffentlicher Kampagnen-Link", der ungewöhnlich häufige, wiederholte Übermittlungen aus derselben Sitzung innerhalb eines kurzen Zeitfensters begrenzt (Rate Limit je Sitzung und Zeitfenster). Die serverseitige Heuristik verarbeitet keine personenbezogenen Identifikationsdaten und wird nicht aus solchen abgeleitet.
- **Antwort**: Die Gesamtheit der Bewertungen eines Teilnehmers zu den Items seiner Teilnehmer-Teilmenge einer Kampagne, bestehend je Item aus genau einer Ist-Bewertung und einem optionalen Freitextkommentar.
- **Auswertung**: Die aggregierte Darstellung der Antworten einer Kampagne im Status "Aktiv" (Zwischenauswertung) oder "Abgeschlossen" (Endauswertung) inklusive der Ist-Scores je Unternehmenswert und je Perspektive (Selbst, Team, Führung).
- **Zwischenauswertung**: Die Auswertung einer Kampagne im Status "Aktiv". Sie ist als vorläufig gekennzeichnet und wird nur stufenweise aktualisiert: Sie beruht jeweils auf den ersten m abgegebenen Antworten, wobei m das größte ganzzahlige Vielfache der Anonymitätsschwelle ist, das die Anzahl abgegebener Antworten nicht übersteigt.
- **Endauswertung**: Die Auswertung einer Kampagne im Status "Abgeschlossen" auf Basis aller abgegebenen Antworten.
- **Anonymitätsschwelle**: Die je Kampagne festgelegte Mindestanzahl an Teilnehmern (ganze Zahl von 3 bis 100, Vorgabewert 5), ab der das System Ist-Scores und Freitextkommentare anzeigt oder exportiert. Sie gilt kampagnenweit für die Anzahl abgegebener Antworten und zusätzlich je Unternehmenswert und Perspektive für die Anzahl beitragender Teilnehmer.
- **Beitragender Teilnehmer**: Ein Teilnehmer, dessen Antwort für einen Unternehmenswert und eine Perspektive mindestens eine Ist-Bewertung eines nicht deaktivierten Items dieser Perspektive mit einer Werte-Zuordnung größer als 0 % zu diesem Unternehmenswert enthält.
- **Verlauf**: Die Entwicklung des Ist-Scores eines Unternehmenswerts je Perspektive über mehrere abgeschlossene Kampagnen hinweg.
- **Skala**: Eine Bewertungsskala mit stufenlosen Dezimalwerten von 1,00 bis 5,00.

## Requirements

### Requirement 1: Administrator-Authentifizierung

**User Story:** Als Administrator möchte ich mich sicher anmelden, damit nur berechtigte Personen Unternehmenswerte, Items, Kampagnen und Auswertungen verwalten können.

#### Acceptance Criteria

1. WENN ein Administrator gültige Anmeldedaten übermittelt, DANN SOLL DAS System innerhalb von 3 Sekunden eine authentifizierte Sitzung erstellen und die Person zur Administrationsoberfläche weiterleiten.
2. WENN ein Administrator ungültige Anmeldedaten übermittelt, DANN SOLL DAS System die Anmeldung ablehnen, keine Sitzung erstellen und eine Fehlermeldung anzeigen, die auf ungültige Anmeldedaten hinweist, ohne mitzuteilen, welches einzelne Feld fehlerhaft war.
3. WENN ein Administrator innerhalb von 15 Minuten fünf aufeinanderfolgende fehlgeschlagene Anmeldeversuche übermittelt, DANN SOLL DAS System weitere Anmeldeversuche für diesen Benutzer für mindestens 15 Minuten ablehnen und eine Fehlermeldung anzeigen, die auf die vorübergehende Sperrung hinweist.
4. WENN eine nicht authentifizierte Person eine Administrationsfunktion aufruft, DANN SOLL DAS System den Zugriff verweigern, keine Daten der Funktion ausliefern und zur Anmeldeseite weiterleiten.
5. WENN ein Administrator die Abmeldung auslöst, DANN SOLL DAS System die Sitzung sofort beenden, das zugehörige Sitzungstoken ungültig machen und zur Anmeldeseite weiterleiten.
6. WÄHREND eine authentifizierte Sitzung 30 Minuten ohne Benutzeraktivität bleibt, SOLL DAS System die Sitzung beenden und beim nächsten Zugriff zur Anmeldeseite weiterleiten.

### Requirement 2: Unternehmenswerte verwalten

**User Story:** Als Administrator möchte ich Unternehmenswerte mit Namen, Beschreibung und Fokussätzen definieren und pflegen, damit die Vorgaben für die Umfrage und die Item-Generierung mein Unternehmen abbilden.

#### Acceptance Criteria

1. WENN ein Administrator einen Unternehmenswert mit einem Namen von 1 bis 100 Zeichen und einer Beschreibung von 0 bis 1.000 Zeichen anlegt, DANN SOLL DAS System den Unternehmenswert speichern und in der Liste der Unternehmenswerte anzeigen.
2. WENN ein Administrator einen Unternehmenswert mit leerem oder ausschließlich aus Leerzeichen bestehendem Namen anlegen will, DANN SOLL DAS System die Speicherung ablehnen, die eingegebenen Daten beibehalten und eine Fehlermeldung anzeigen, die auf den fehlenden Namen hinweist.
3. WENN ein Administrator einen Unternehmenswert mit einem Namen anlegen will, der bereits für einen bestehenden Unternehmenswert vergeben ist, DANN SOLL DAS System die Speicherung ablehnen und eine Fehlermeldung anzeigen, die auf den bereits vorhandenen Namen hinweist.
4. WENN ein Administrator einem Unternehmenswert einen Fokussatz mit einem Text von 1 bis 500 Zeichen hinzufügt, DANN SOLL DAS System den Fokussatz dem Unternehmenswert zuordnen und in der Liste der Fokussätze dieses Unternehmenswerts anzeigen.
5. WENN ein Administrator einen Fokussatz mit leerem oder über 500 Zeichen langem Text hinzufügen oder bearbeiten will, DANN SOLL DAS System die Speicherung ablehnen, die eingegebenen Daten beibehalten und eine Fehlermeldung anzeigen, die auf die ungültige Textlänge hinweist.
6. WENN ein Administrator einen bestehenden Fokussatz eines Unternehmenswerts bearbeitet oder entfernt, DANN SOLL DAS System die Änderung speichern und die aktualisierte Liste der Fokussätze dieses Unternehmenswerts anzeigen.
7. WENN ein Administrator einen bestehenden Unternehmenswert mit gültigen Daten bearbeitet, DANN SOLL DAS System die geänderten Daten (Name, Beschreibung und Fokussätze) auch dann speichern, wenn der Unternehmenswert von verwendeten Item-Versionen referenziert wird, und in der Liste der Unternehmenswerte anzeigen.
8. WENN ein Administrator einen Unternehmenswert löscht, der von keinem Item des Kampagnen-Snapshots einer aktiven Kampagne über eine Werte-Zuordnung referenziert wird und von keiner verwendeten Item-Version referenziert wird, DANN SOLL DAS System den Unternehmenswert samt zugehöriger Fokussätze entfernen und nicht mehr in der Liste anzeigen.
9. WENN ein Administrator einen Unternehmenswert löschen will, der von mindestens einem Item des Kampagnen-Snapshots einer aktiven Kampagne über eine Werte-Zuordnung referenziert wird, DANN SOLL DAS System die Löschung ablehnen, den Unternehmenswert unverändert beibehalten und eine Fehlermeldung anzeigen, die auf die Verwendung in einer aktiven Kampagne hinweist.
10. WENN ein Administrator einen Unternehmenswert löschen will, der von mindestens einer verwendeten Item-Version über eine Werte-Zuordnung referenziert wird, DANN SOLL DAS System die Löschung ablehnen, den Unternehmenswert unverändert beibehalten und eine Fehlermeldung anzeigen, die darauf hinweist, dass der Unternehmenswert von verwendeten Item-Versionen referenziert wird.
11. WENN ein Administrator die Liste der Unternehmenswerte öffnet, DANN SOLL DAS System alle definierten Unternehmenswerte anzeigen.
12. WENN kein Unternehmenswert definiert ist und ein Administrator die Liste öffnet, DANN SOLL DAS System einen Hinweis anzeigen, dass noch keine Unternehmenswerte vorhanden sind.
13. WENN durch das Löschen eines Unternehmenswerts eine nicht verwendete Item-Version keine Werte-Zuordnung mit einer Gewichtung größer als 0 % mehr besitzt, DANN SOLL DAS System den Item-Status dieser Item-Version auf "zur Prüfung" setzen und sie aus den Kampagnen-Pools von Kampagnen im Status "Entwurf" herausnehmen.

### Requirement 3: KI-gestützte Item-Generierung

**User Story:** Als Administrator möchte ich aus den Vorgaben der Unternehmenswerte automatisch Umfrage-Items generieren lassen, damit ich die Umfrage effizient und konsistent aus Name, Beschreibung und Fokussätzen aufbauen kann.

#### Acceptance Criteria

1. WENN ein Administrator die Item-Generierung für einen Unternehmenswert auslöst, der mindestens einen Fokussatz besitzt, DANN SOLL DAS System aus Namen, Beschreibung und Fokussätzen dieses Unternehmenswerts KI-gestützt ein oder mehrere Items als Vorschläge erzeugen und zur Prüfung anzeigen.
2. WENN ein Administrator die Item-Generierung für einen Unternehmenswert auslöst, der keinen Fokussatz besitzt, DANN SOLL DAS System die Generierung ablehnen und eine Fehlermeldung anzeigen, die auf den fehlenden Fokussatz hinweist.
3. WENN das System Items zu einem Fokussatz generiert, DANN SOLL DAS System je Fokussatz drei Item-Varianten erzeugen, je eine für die Perspektive Selbst, Team und Führung, deren Formulierung jeweils die zugeordnete Perspektive ausdrückt.
4. DAS System SOLL jedes generierte Item mit genau einer Perspektive (Selbst, Team oder Führung), einem Item-Typ (Frage oder Situation/Use-Case) und mindestens einer vorgeschlagenen Werte-Zuordnung mit einer Gewichtung größer als 0 % erzeugen.
5. WENN das System ein Item generiert, DANN SOLL DAS System zu diesem Item die Perspektive, die Werte-Zuordnungen und deren Gewichtungen als änderbaren Vorschlag bereitstellen.
6. WENN ein Administrator die vom System vorgeschlagene Perspektive oder den Item-Text vor der Freigabe des Items ändert, DANN SOLL DAS System die geänderte Perspektive und den geänderten Text übernehmen und die Gültigkeitsregeln für Items gemäß Anforderung 5 anwenden.
7. WENN ein Administrator eine vom System vorgeschlagene Werte-Zuordnung oder deren Gewichtung vor der Freigabe des Items ändert, DANN SOLL DAS System die geänderten Werte-Zuordnungen und Gewichtungen anstelle des Vorschlags übernehmen und die Gültigkeitsregeln für Items gemäß Anforderung 5 anwenden.
8. WENN das System ein Item generiert, DANN SOLL DAS System dieses Item als Vorschlag im Status "zur Prüfung" bereitstellen und noch nicht in eine Kampagne aufnehmen oder in einer Umfrage verwenden.
9. WENN ein Administrator ein generiertes Item freigibt, DANN SOLL DAS System das Item mit seiner zum Zeitpunkt der Freigabe gültigen Perspektive sowie seinen Werte-Zuordnungen und Gewichtungen im Status "freigegeben" speichern und für die Verwendung in Kampagnen bereitstellen.
10. WENN ein Administrator ein generiertes Item vor der Freigabe bearbeitet, DANN SOLL DAS System die geänderten Angaben übernehmen und die Gültigkeitsregeln für Items gemäß Anforderung 5 anwenden.
11. WENN ein Administrator ein generiertes Item verwirft, DANN SOLL DAS System das Item nicht speichern und aus der Liste der Vorschläge entfernen.
12. WENN die KI-gestützte Generierung fehlschlägt, DANN SOLL DAS System sowohl keine Items speichern als auch die Vorgaben des Unternehmenswerts unverändert beibehalten als auch eine Fehlermeldung anzeigen, die auf den fehlgeschlagenen Generierungsvorgang und die Möglichkeit eines erneuten Versuchs hinweist.
13. WENN ein Administrator die KI-gestützte Verfeinerung für ein generiertes oder bestehendes, nicht verwendetes Item im Status "zur Prüfung" oder "deaktiviert" auslöst und optional einen Anweisungstext von 0 bis 1.000 Zeichen angibt, DANN SOLL DAS System die Item-Version unter Berücksichtigung des Anweisungstexts und der Vorgaben der zugeordneten Unternehmenswerte KI-gestützt überarbeiten und das Ergebnis als Vorschlag im Status "zur Prüfung" zur Prüfung anzeigen.
14. WENN ein Administrator die KI-gestützte Verfeinerung für ein verwendetes Item (Item-Status "freigegeben" oder "deaktiviert") auslöst und optional einen Anweisungstext von 0 bis 1.000 Zeichen angibt, DANN SOLL DAS System das Ergebnis der Verfeinerung als neue Item-Version derselben Item-Familie mit der nächsthöheren Versionsnummer im Status "zur Prüfung" zur Prüfung anzeigen und die verwendete Item-Version unverändert beibehalten.
15. WENN das System ein verfeinertes Item oder eine durch Verfeinerung entstandene neue Item-Version bereitstellt, DANN SOLL DAS System das verfeinerte Item bzw. die neue Item-Version erst nach erneuter Freigabe durch einen Administrator und erfolgreicher Anwendung der Gültigkeitsregeln gemäß Anforderung 5 in Kampagnen und Umfragen verwenden.
16. WENN die KI-gestützte Verfeinerung fehlschlägt, DANN SOLL DAS System sowohl keine Änderung am Item und keine neue Item-Version speichern als auch das Item und die Vorgaben des Unternehmenswerts unverändert beibehalten als auch eine Fehlermeldung anzeigen, die auf den fehlgeschlagenen Verfeinerungsvorgang und die Möglichkeit eines erneuten Versuchs hinweist.

### Requirement 4: Item-Vorgaben exportieren und Items importieren

**User Story:** Als Administrator möchte ich die Datenstruktur der Unternehmenswerte exportieren und extern erstellte Items importieren, damit ich Items alternativ in einer externen KI oder einem anderen Hilfsmittel erstellen und im System weiterverwenden kann.

#### Acceptance Criteria

1. WENN ein Administrator den Export der Item-Vorgaben auslöst und mindestens ein Unternehmenswert definiert ist, DANN SOLL DAS System eine JSON-Datei erzeugen, die alle Unternehmenswerte mit Name, Beschreibung und Fokussätzen sowie eine Schemabeschreibung für die externe Item-Erstellung enthält.
2. DAS System SOLL die Schemabeschreibung der Export-Datei so ausgeben, dass sie je Item den Item-Text (1 bis 500 Zeichen), den Item-Typ (Frage oder Situation/Use-Case), genau eine Perspektive (Selbst, Team oder Führung) und Werte-Zuordnungen mit Name des Unternehmenswerts und Gewichtung von 0 % bis 100 % beschreibt.
3. WENN ein Administrator den Export der Item-Vorgaben auslöst und kein Unternehmenswert definiert ist, DANN SOLL DAS System den Export ablehnen, keine Datei erzeugen und eine Fehlermeldung anzeigen, die auf die fehlenden Unternehmenswerte hinweist.
4. WENN ein Administrator eine JSON-Datei mit Items importiert, DANN SOLL DAS System jedes Item der Datei gegen dieselben Gültigkeitsregeln wie bei der Item-Verwaltung gemäß Anforderung 5 prüfen: Text von 1 bis 500 Zeichen, gültiger Item-Typ, genau eine gültige Perspektive, Gewichtungen von 0 % bis 100 % und mindestens eine Werte-Zuordnung mit einer Gewichtung größer als 0 %.
5. WENN ein importiertes Item eine Werte-Zuordnung zu einem Unternehmenswert enthält, der im System nicht existiert, DANN SOLL DAS System dieses Item als ungültig behandeln.
6. WENN ein importiertes Item alle Gültigkeitsregeln erfüllt, DANN SOLL DAS System das Item im Status "zur Prüfung" anlegen und nicht sofort freigeben.
7. WENN ein importiertes Item mindestens eine Gültigkeitsregel verletzt, DANN SOLL DAS System dieses Item nicht speichern und im Importbericht mit seiner Position in der Datei und dem Ablehnungsgrund melden, während gültige Items derselben Datei weiterhin importiert werden.
8. WENN die importierte Datei kein gültiges JSON ist oder nicht dem Schema der Export-Datei entspricht, DANN SOLL DAS System den gesamten Import ablehnen, kein Item speichern und eine Fehlermeldung anzeigen, die auf den ungültigen Dateiaufbau hinweist.
9. WENN der Import abgeschlossen ist, DANN SOLL DAS System einen Importbericht mit der Anzahl der angelegten und der abgelehnten Items als ganze Zahlen anzeigen.

### Requirement 5: Items verwalten

**User Story:** Als Administrator möchte ich Items bearbeiten und ihre gewichteten Werte-Zuordnungen pflegen, damit jedes Item die zutreffenden Unternehmenswerte im richtigen Verhältnis abbildet.

#### Acceptance Criteria

1. WENN ein Administrator ein Item mit einem Text von 1 bis 500 Zeichen, einem Item-Typ (Frage oder Situation/Use-Case) und genau einer Perspektive (Selbst, Team oder Führung) speichert, DANN SOLL DAS System das Item im Status "zur Prüfung" speichern und eine Erfolgsbestätigung anzeigen.
2. WENN ein Administrator ein Item mit leerem Text oder einem Text über 500 Zeichen speichern will, DANN SOLL DAS System die Speicherung ablehnen, die eingegebenen Daten beibehalten und eine Fehlermeldung anzeigen, die auf die ungültige Textlänge hinweist.
3. DAS System SOLL jedes Item mit genau einer Perspektive (Selbst, Team oder Führung) als Pflichteigenschaft führen.
4. WENN ein Administrator ein Item ohne eine der Perspektiven Selbst, Team oder Führung speichern will, DANN SOLL DAS System die Speicherung ablehnen, die eingegebenen Daten beibehalten und eine Fehlermeldung anzeigen, die auf die fehlende gültige Perspektive hinweist.
5. WENN ein Administrator die Perspektive eines Items ändert, DANN SOLL DAS System die geänderte Perspektive speichern und dem Administrator ermöglichen, den Item-Text an die geänderte Perspektive anzupassen.
6. WENN ein Administrator eine Werte-Zuordnung eines Items mit einer Gewichtung festlegt, DANN SOLL DAS System die Gewichtung nur als Prozentwert von 0 % bis 100 % akzeptieren.
7. WENN ein Administrator eine Werte-Zuordnung mit einer Gewichtung kleiner als 0 % oder größer als 100 % speichern will, DANN SOLL DAS System die Speicherung ablehnen, die eingegebenen Daten beibehalten und eine Fehlermeldung anzeigen, die auf den zulässigen Bereich von 0 % bis 100 % hinweist.
8. WENN ein Administrator ein Item ohne mindestens eine Werte-Zuordnung mit einer Gewichtung größer als 0 % speichern will, DANN SOLL DAS System die Speicherung ablehnen, die eingegebenen Daten beibehalten und eine Fehlermeldung anzeigen, die darauf hinweist, dass das Item mindestens einem Unternehmenswert mit einer Gewichtung größer als 0 % zugeordnet sein muss.
9. DAS System SOLL zulassen, dass ein Item mehreren Unternehmenswerten mit jeweils eigener Gewichtung zugeordnet ist, wobei unterschiedliche Zuordnungen desselben Items unterschiedliche Gewichtungen haben dürfen und mehrere Zuordnungen die Gewichtung 100 % tragen dürfen.
10. WENN das System zu einem Item Werte-Zuordnungen und Gewichtungen vorschlägt, DANN SOLL DAS System dem Administrator ermöglichen, diese vorgeschlagenen Werte-Zuordnungen und Gewichtungen hinzuzufügen, zu ändern oder zu entfernen, solange die Gültigkeitsregeln gemäß den Kriterien 6 bis 9 eingehalten werden.
11. WENN ein Administrator ein bestehendes, nicht verwendetes Item bearbeitet und speichert, DANN SOLL DAS System die geänderten Angaben mit den gleichen Gültigkeitsregeln wie bei der Neuanlage speichern und eine Erfolgsbestätigung anzeigen.
12. DAS System SOLL jede Item-Version mit genau einem Item-Status führen: "zur Prüfung", "freigegeben" oder "deaktiviert".
13. WENN ein Administrator ein Item im Status "zur Prüfung" oder "deaktiviert", das die Gültigkeitsregeln der Kriterien 1 bis 9 erfüllt, freigibt, DANN SOLL DAS System den Item-Status auf "freigegeben" setzen und das Item für die Zuordnung zu Kampagnen-Pools bereitstellen.
14. WENN ein Administrator ein Item freigeben will, das die Gültigkeitsregeln der Kriterien 1 bis 9 nicht erfüllt, DANN SOLL DAS System die Freigabe ablehnen, den Item-Status beibehalten und eine Fehlermeldung anzeigen, die die verletzte Regel benennt.
15. WENN ein Administrator ein nicht verwendetes Item im Status "freigegeben" bearbeitet und speichert, DANN SOLL DAS System die geänderten Angaben speichern und den Item-Status auf "zur Prüfung" setzen, sodass das Item erneut freigegeben werden muss.
16. WENN ein Administrator ein Item im Status "freigegeben" außerhalb einer laufenden Kampagne deaktiviert, DANN SOLL DAS System ausschließlich den Item-Status auf "deaktiviert" setzen, den Inhalt der Item-Version unverändert beibehalten und das Item nicht mehr für die Zuordnung zu Kampagnen-Pools bereitstellen.
17. DAS System SOLL ausschließlich Items im Status "freigegeben" für die Zuordnung zu einem Kampagnen-Pool und für die Verwendung in Umfragen bereitstellen.
18. WENN ein Administrator ein nicht verwendetes Item im Status "zur Prüfung" oder "deaktiviert" bearbeitet oder per KI verfeinert oder eine neue Item-Version entsteht, DANN SOLL DAS System die betroffene Item-Version bis zur erneuten Freigabe nicht in Umfragen verwenden.
19. DAS System SOLL eine Item-Version als verwendet kennzeichnen, sobald eine Kampagne aktiviert wurde, deren Kampagnen-Pool diese Item-Version enthält; die Zugehörigkeit zum Kampagnen-Pool einer Kampagne im Status "Entwurf" SOLL DAS System nicht als Verwendung werten.
20. DAS System SOLL Item-Text, Item-Typ, Perspektive, Werte-Zuordnungen und Gewichtungen einer verwendeten Item-Version unveränderlich führen.
21. WENN ein Administrator ein verwendetes Item (Item-Status "freigegeben" oder "deaktiviert") bearbeitet und speichert, DANN SOLL DAS System die geänderten Angaben mit den gleichen Gültigkeitsregeln wie bei der Neuanlage als neue Item-Version derselben Item-Familie mit der nächsthöheren Versionsnummer im Status "zur Prüfung" speichern, die verwendete Item-Version unverändert beibehalten und eine Erfolgsbestätigung anzeigen.
22. DAS System SOLL eine neue Item-Version für Kampagnen und Ist-Score wie ein neues Item behandeln, sodass Ist-Bewertungen früherer Item-Versionen nicht der neuen Item-Version zugerechnet werden und die neue Item-Version erst nach Freigabe einem Kampagnen-Pool zugeordnet werden kann.
23. DAS System SOLL die vorherige Item-Version nach dem Anlegen einer neuen Item-Version mit unverändertem Inhalt und unverändertem Item-Status beibehalten, sodass sie im Status "freigegeben" weiterhin neuen Kampagnen-Pools zugeordnet werden kann und beide Item-Versionen nebeneinander bestehen.
24. WENN ein Administrator die Versionshistorie einer Item-Familie öffnet, DANN SOLL DAS System alle Item-Versionen dieser Item-Familie mit Versionsnummer, Item-Status und Kennzeichnung als verwendet oder nicht verwendet anzeigen.
25. WENN ein Administrator eine verwendete Item-Version im Status "deaktiviert" unverändert erneut freigibt, DANN SOLL DAS System ausschließlich den Item-Status auf "freigegeben" setzen, keine neue Item-Version anlegen und die Item-Version für die Zuordnung zu später erstellten Kampagnen-Pools bereitstellen.
26. WENN ein Administrator ein Item löscht, dessen Item-Version nicht Teil eines Kampagnen-Snapshots einer Kampagne im Status "Aktiv" oder "Abgeschlossen" ist, DANN SOLL DAS System die Item-Version entfernen, sie aus den Kampagnen-Pools von Kampagnen im Status "Entwurf" herausnehmen und eine Erfolgsbestätigung anzeigen.
27. WENN ein Administrator eine Item-Version löschen will, die Teil mindestens eines Kampagnen-Snapshots einer Kampagne im Status "Aktiv" oder "Abgeschlossen" ist, DANN SOLL DAS System die Löschung ablehnen, die Item-Version unverändert beibehalten und eine Fehlermeldung anzeigen, die darauf hinweist, dass die Item-Version in einer Kampagne verwendet wurde und nicht gelöscht werden kann.
28. WENN ein Administrator einen Unternehmenswert auswählt, DANN SOLL DAS System alle Items anzeigen, die diesem Unternehmenswert mit einer Gewichtung größer als 0 % zugeordnet sind.
29. DAS System SOLL zulassen, dass Items jederzeit generiert und verwaltet werden, unabhängig davon, ob Kampagnen im Status "Aktiv" oder "Abgeschlossen" bestehen.
30. WÄHREND eine Kampagne den Status "Aktiv" hat, SOLL DAS System den Teilnehmern dieser Kampagne ausschließlich den Stand der Items zum Zeitpunkt des Kampagnenstarts (Snapshot-Version) anzeigen, einschließlich Item-Text, Item-Typ, Perspektive, Werte-Zuordnungen und Gewichtungen, wobei in der Kampagne deaktivierte Items nicht angezeigt werden.
31. WENN nach dem Start einer Kampagne ein Item generiert oder eine neue Item-Version angelegt wird, DANN SOLL DAS System den Kampagnen-Snapshot laufender und abgeschlossener Kampagnen unverändert beibehalten.

### Requirement 6: Kampagne erstellen und steuern

**User Story:** Als Administrator möchte ich Kampagnen als Erhebungsfenster erstellen und deren Status steuern, damit ich definierte Erhebungszeiträume durchführen kann.

#### Acceptance Criteria

1. WENN ein Administrator eine Kampagne mit einem Titel von 1 bis 200 Zeichen, Startdatum und Enddatum erstellt, DANN SOLL DAS System die Kampagne mit dem Status "Entwurf" speichern.
2. WENN ein Administrator eine Kampagne mit leerem oder über 200 Zeichen langem Titel erstellen will, DANN SOLL DAS System die Erstellung ablehnen, die eingegebenen Daten beibehalten und eine Fehlermeldung anzeigen, die auf den ungültigen Titel hinweist.
3. WENN ein Administrator eine Kampagne mit einem Enddatum erstellt, das vor oder gleich dem Startdatum liegt, DANN SOLL DAS System die Erstellung ablehnen, die eingegebenen Daten beibehalten und eine Fehlermeldung anzeigen, die auf den ungültigen Zeitraum hinweist.
4. WENN ein Administrator einer Kampagne im Status "Entwurf" Items (Fragen und Situationen/Use-Cases) im Status "freigegeben" als Kampagnen-Pool zuordnet, DANN SOLL DAS System diese Zuordnungen für die Kampagne speichern und die Unternehmenswerte der Kampagne aus den Werte-Zuordnungen der Items ableiten und anzeigen.
5. WENN ein Administrator einer Kampagne ein Item zuordnen will, das nicht den Status "freigegeben" hat (Status "zur Prüfung" oder "deaktiviert"), DANN SOLL DAS System die Zuordnung ablehnen, den Kampagnen-Pool unverändert beibehalten und eine Fehlermeldung anzeigen, die darauf hinweist, dass nur freigegebene Items verwendet werden können.
6. WENN ein Administrator eine Kampagne im Status "Entwurf" die Item-Anzahl je Teilnehmer als ganze Zahl von 1 bis zur Größe des Kampagnen-Pools festlegt, DANN SOLL DAS System diesen Wert für die Kampagne speichern.
7. WENN ein Administrator beim Erstellen einer Kampagne im Status "Entwurf" den Kampagnen-Pool einer früheren Kampagne im Status "Aktiv" oder "Abgeschlossen" übernimmt, DANN SOLL DAS System den Kampagnen-Pool der neuen Kampagne mit exakt denselben Item-Versionen vorbelegen, die Anonymitätsschwelle der früheren Kampagne als änderbaren Wert vorbelegen, die Item-Anzahl je Teilnehmer der früheren Kampagne als änderbaren Wert vorbelegen und den vorbelegten Kampagnen-Pool wie gewohnt anpassbar lassen.
8. WENN beim Übernehmen des Kampagnen-Pools einer früheren Kampagne mindestens eine Item-Version nicht mehr den Status "freigegeben" hat, DANN SOLL DAS System diese Item-Versionen nicht in den Kampagnen-Pool der neuen Kampagne übernehmen und in einem Hinweis alle nicht übernommenen Item-Versionen benennen.
9. WENN ein Administrator eine Kampagne im Status "Entwurf" ohne festgelegte Item-Anzahl je Teilnehmer oder mit einer Item-Anzahl je Teilnehmer außerhalb des Bereichs von 1 bis zur Größe des Kampagnen-Pools aktiviert, DANN SOLL DAS System die Aktivierung ablehnen, den Status "Entwurf" beibehalten und eine Fehlermeldung anzeigen, die auf die ungültige Item-Anzahl je Teilnehmer hinweist.
10. WENN ein Administrator eine Kampagne im Status "Entwurf" ohne mindestens ein zugeordnetes Item aktiviert, DANN SOLL DAS System die Aktivierung ablehnen, den Status "Entwurf" beibehalten und eine Fehlermeldung anzeigen, die auf das fehlende Item hinweist.
11. WENN ein Administrator eine Kampagne im Status "Entwurf" aktiviert, deren Kampagnen-Pool mindestens ein Item enthält, das nicht mehr den Status "freigegeben" hat, DANN SOLL DAS System die Aktivierung ablehnen, den Status "Entwurf" beibehalten und eine Fehlermeldung anzeigen, die die betroffenen Items benennt.
12. WENN ein Administrator eine Kampagne im Status "Entwurf" mit mindestens einem zugeordneten Item, einer gültigen Item-Anzahl je Teilnehmer und einer gültigen Anonymitätsschwelle aktiviert, DANN SOLL DAS System den Status auf "Aktiv" setzen.
13. WENN eine Kampagne den Status "Aktiv" erhält, DANN SOLL DAS System den Kampagnen-Pool einschließlich Item-Text, Item-Typ und Perspektive jedes Items sowie die Item-Werte-Zuordnungen und deren Gewichtungen als Kampagnen-Snapshot einfrieren, jede Item-Version des Kampagnen-Pools als verwendet kennzeichnen, jedes Item im Kampagnen-Snapshot als aktiv kennzeichnen und diesen Kampagnen-Snapshot für alle Umfragen und Berechnungen dieser Kampagne verwenden.
14. WENN ein Administrator den Kampagnen-Pool oder die Item-Werte-Zuordnungen oder deren Gewichtungen einer Kampagne im Status "Aktiv" oder "Abgeschlossen" ändern will, DANN SOLL DAS System die Änderung ablehnen, den Kampagnen-Snapshot unverändert beibehalten und eine Fehlermeldung anzeigen, die auf den unveränderlichen Kampagnen-Snapshot hinweist; ausgenommen ist ausschließlich die Deaktivierung eines Items gemäß den Kriterien 15 bis 21.
15. WENN ein Administrator in einer Kampagne im Status "Aktiv" ein Item des Kampagnen-Pools deaktiviert, DANN SOLL DAS System dieses Item im Kampagnen-Snapshot dieser Kampagne als deaktiviert kennzeichnen (Item bleibt im Kampagnen-Snapshot erhalten), den Zeitpunkt der Deaktivierung speichern, den Item-Status des Items auf "deaktiviert" setzen und eine Erfolgsbestätigung anzeigen; die Kampagnen-Snapshots anderer Kampagnen bleiben unverändert.
16. WENN ein Administrator die Deaktivierung eines Items für eine Kampagne im Status "Entwurf" oder "Abgeschlossen" auslöst, DANN SOLL DAS System die Deaktivierung für diese Kampagne ablehnen, den Kampagnen-Snapshot unverändert beibehalten und eine Fehlermeldung anzeigen, die darauf hinweist, dass die Deaktivierung nur für Kampagnen im Status "Aktiv" möglich ist.
17. WENN ein Item in einer Kampagne deaktiviert wurde, DANN SOLL DAS System dieses Item ab dem Zeitpunkt der Deaktivierung nicht mehr in die Teilnehmer-Teilmenge neuer Teilnehmer dieser Kampagne aufnehmen.
18. WENN ein Item in einer Kampagne deaktiviert wurde, DANN SOLL DAS System die bereits abgegebenen Ist-Bewertungen und Freitextkommentare zu diesem Item gespeichert lassen und von der Berechnung der Ist-Scores, der Anzeige der Auswertung und dem Export dieser Kampagne ausschließen.
19. WENN durch die Deaktivierung eines Items die Anzahl der noch aktiven Items des Kampagnen-Pools unter die Item-Anzahl je Teilnehmer sinkt, DANN SOLL DAS System neuen Teilnehmern alle verbleibenden aktiven Items als Teilnehmer-Teilmenge zuweisen und dem Administrator einen Hinweis auf die verringerte Größe der Teilnehmer-Teilmenge anzeigen.
20. WENN ein Administrator das letzte noch aktive Item einer Kampagne deaktivieren will, DANN SOLL DAS System vor der Deaktivierung eine Warnung anzeigen, dass neue Teilnehmer die Umfrage danach nicht mehr öffnen können, und die Deaktivierung erst nach Bestätigung durch den Administrator ausführen.
21. WENN ein Administrator ein in der Kampagne deaktiviertes Item in derselben Kampagne wieder aktivieren will, DANN SOLL DAS System dies ablehnen, den Kampagnen-Snapshot unverändert beibehalten und eine Fehlermeldung anzeigen, die darauf hinweist, dass ein deaktiviertes Item nur in später erstellten Kampagnen erneut verwendet werden kann.
22. WENN ein Administrator eine in einer Kampagne deaktivierte, verwendete Item-Version unverändert erneut freigibt, DANN SOLL DAS System ausschließlich den Item-Status auf "freigegeben" setzen, die Item-Version für ausschließlich später erstellte Kampagnen bereitstellen und die Kampagnen-Snapshots laufender und abgeschlossener Kampagnen unverändert beibehalten.
23. WENN ein Administrator eine in einer Kampagne deaktivierte, verwendete Item-Version überarbeitet (bearbeitet oder per KI verfeinert), DANN SOLL DAS System gemäß den Anforderungen 3 und 5 eine neue Item-Version im Status "zur Prüfung" anlegen, die deaktivierte Item-Version unverändert im Status "deaktiviert" beibehalten, die neue Item-Version nach erneuter Freigabe ausschließlich für Kampagnen verwenden, die danach erstellt und aktiviert werden, und die Kampagnen-Snapshots laufender und abgeschlossener Kampagnen unverändert beibehalten.
24. WENN ein Administrator Änderungen an Item-Text, Item-Typ, Perspektive, Item-Werte-Zuordnungen oder Gewichtungen eines verwendeten Items für eine künftige Messung verwenden will, DANN SOLL DAS System diese Änderungen ausschließlich durch eine neue Item-Version in einer neu erstellten Kampagne wirksam machen, die den zum Zeitpunkt ihrer Erstellung gültigen Stand der zugeordneten Item-Versionen als eigenen Kampagnen-Snapshot erfasst.
25. WENN ein Administrator eine Kampagne im Status "Aktiv" schließt, DANN SOLL DAS System den Status auf "Abgeschlossen" setzen.
26. WENN ein Administrator einen Statuswechsel auslöst, der nicht der Sequenz Entwurf → Aktiv → Abgeschlossen entspricht, DANN SOLL DAS System den Statuswechsel ablehnen und den bestehenden Status beibehalten.
27. WÄHREND eine Kampagne den Status "Abgeschlossen" hat, SOLL DAS System weitere Antworten für diese Kampagne ablehnen.
28. WENN ein Administrator eine Kampagne erstellt, DANN SOLL DAS System die Anonymitätsschwelle mit dem Vorgabewert 5 belegen; WENN ein Administrator die Anonymitätsschwelle einer Kampagne im Status "Entwurf" als ganze Zahl von 3 bis 100 festlegt, DANN SOLL DAS System diesen Wert für die Kampagne speichern.
29. WENN ein Administrator eine Anonymitätsschwelle außerhalb des Bereichs von 3 bis 100 oder keine ganze Zahl festlegen will, DANN SOLL DAS System die Speicherung ablehnen, die eingegebenen Daten beibehalten und eine Fehlermeldung anzeigen, die auf den zulässigen Bereich von 3 bis 100 hinweist.
30. WENN eine Kampagne den Status "Aktiv" erhält, DANN SOLL DAS System die Anonymitätsschwelle zusammen mit dem Kampagnen-Snapshot einfrieren; WENN ein Administrator die Anonymitätsschwelle einer Kampagne im Status "Aktiv" oder "Abgeschlossen" ändern will, DANN SOLL DAS System die Änderung ablehnen und eine Fehlermeldung anzeigen, die auf den unveränderlichen Kampagnen-Snapshot hinweist.

### Requirement 7: Kampagne verteilen und Mehrfachteilnahme verhindern

**User Story:** Als Administrator möchte ich je Kampagne genau einen Verteilmodus wählen – einen öffentlichen Kampagnen-Link oder individuelle Einmal-Links per E-Mail –, damit relevante Mitarbeitende anonym an der Umfrage teilnehmen und eine Mehrfachteilnahme verhindert wird.

#### Acceptance Criteria

1. WENN ein Administrator eine Kampagne verteilt, DANN SOLL DAS System genau einen Verteilmodus je Kampagne zulassen, entweder "öffentlicher Kampagnen-Link" ODER "individuelle Einmal-Links per E-Mail".
2. WENN ein Administrator im Verteilmodus "öffentlicher Kampagnen-Link" für eine Kampagne im Status "Aktiv" einen Kampagnen-Link erzeugt, DANN SOLL DAS System einen öffentlichen Kampagnen-Link erzeugen, der genau dieser Kampagne zugeordnet ist und sich von jedem zuvor erzeugten Kampagnen-Link unterscheidet.
3. WENN ein Teilnehmer im Verteilmodus "öffentlicher Kampagnen-Link" den Kampagnen-Link einer Kampagne im Status "Aktiv" öffnet und die Teilnahmekennung keine vorherige Teilnahme an dieser Kampagne ausweist, DANN SOLL DAS System die Umfrage dieser Kampagne mit der Teilnehmer-Teilmenge anzeigen.
4. WENN ein Teilnehmer im Verteilmodus "öffentlicher Kampagnen-Link" den Kampagnen-Link öffnet und die Teilnahmekennung (Cookie oder lokal erzeugter Code) eine vorherige Teilnahme an dieser Kampagne ausweist, DANN SOLL DAS System den Zugang zur Umfrage ablehnen und einen Hinweis anzeigen, dass bereits teilgenommen wurde.
5. WENN im Verteilmodus "öffentlicher Kampagnen-Link" aus derselben Sitzung innerhalb eines kurzen Zeitfensters ungewöhnlich häufige, wiederholte Übermittlungen eingehen, DANN SOLL DAS System diese Übermittlungen anonym über die serverseitige Heuristik begrenzen oder ablehnen.
6. DAS System SOLL die Teilnahmekennung und die Daten der serverseitigen Heuristik ohne personenbezogene Identifikationsdaten führen und nicht aus solchen ableiten.
7. WENN ein Administrator im Verteilmodus "individuelle Einmal-Links per E-Mail" einer Kampagne im Status "Aktiv" 1 bis 10.000 E-Mail-Adressen übergibt, DANN SOLL DAS System je Adresse einen eindeutigen individuellen Einmal-Link erzeugen, diesen versenden, ausschließlich einen anonymen Einmal-Token ohne Zuordnung zur E-Mail-Adresse dauerhaft speichern und keine E-Mail-Adresse speichern.
8. DAS System SOLL jeden Einmal-Link und jeden Einmal-Token so erzeugen, dass er sich von jedem zuvor erzeugten Einmal-Link und Einmal-Token unterscheidet.
9. WENN ein Teilnehmer im Verteilmodus "individuelle Einmal-Links per E-Mail" einen gültigen, noch nicht verwendeten Einmal-Link einer Kampagne im Status "Aktiv" öffnet, DANN SOLL DAS System die Umfrage dieser Kampagne mit der Teilnehmer-Teilmenge anzeigen.
10. WENN ein Teilnehmer einen Einmal-Link öffnet, über den die Umfrage bereits erfolgreich übermittelt wurde, DANN SOLL DAS System den Zugang zur Umfrage ablehnen, die gespeicherte Antwort unverändert beibehalten und einen Hinweis anzeigen, dass bereits teilgenommen wurde.
11. WENN ein Teilnehmer einen gültigen Kampagnen-Link oder Einmal-Link einer Kampagne öffnet, die nicht den Status "Aktiv" hat (Status "Entwurf" oder "Abgeschlossen"), DANN SOLL DAS System den Zugang zur Umfrage ablehnen und für beide Status denselben einheitlichen Hinweis anzeigen, dass die Umfrage derzeit nicht verfügbar ist, ohne zwischen den Status "Entwurf" und "Abgeschlossen" zu unterscheiden.
12. WENN ein Teilnehmer einen gültigen, noch nicht verwendeten Kampagnen-Link oder Einmal-Link einer Kampagne im Status "Aktiv" öffnet, in deren Kampagnen-Pool kein aktives Item mehr vorhanden ist, DANN SOLL DAS System den Zugang zur Umfrage ablehnen, den Einmal-Link unverbraucht lassen und denselben einheitlichen Hinweis anzeigen, dass die Umfrage derzeit nicht verfügbar ist.
13. WENN ein Teilnehmer einen Kampagnen-Link oder Einmal-Link öffnet, der keiner gespeicherten Kampagne bzw. keinem gespeicherten Einmal-Token entspricht, DANN SOLL DAS System eine Fehlermeldung anzeigen, die auf den ungültigen Link hinweist.
14. DAS System SOLL im Verteilmodus "öffentlicher Kampagnen-Link" die browserbasierte Mehrfachteilnahme-Erkennung als Best-Effort-Verfahren ausweisen, dessen Wirkung durch Inkognito-Modus, einen anderen Browser oder gelöschten Browser-Speicher umgangen werden kann und das durch die serverseitige Heuristik reduziert, aber nicht vollständig ausgeschlossen wird.
15. WENN ein Administrator für eine Kampagne im Verteilmodus "öffentlicher Kampagnen-Link", die bereits einen gültigen Kampagnen-Link besitzt, einen neuen Kampagnen-Link erzeugt, DANN SOLL DAS System den bisherigen Kampagnen-Link sofort ungültig machen, den neuen Kampagnen-Link als einzigen gültigen Kampagnen-Link dieser Kampagne speichern und die bereits erfassten Teilnahmen unverändert beibehalten.
16. WENN ein Teilnehmer einen ungültig gemachten Kampagnen-Link öffnet, DANN SOLL DAS System die Fehlermeldung zum ungültigen Link gemäß Kriterium 13 anzeigen.
17. DAS System SOLL die Erkennung einer vorherigen Teilnahme über die Teilnahmekennung je Kampagne und unabhängig vom verwendeten Kampagnen-Link durchführen, sodass ein Teilnehmer nach dem Ersetzen des Kampagnen-Links über den neuen Kampagnen-Link nicht erneut teilnehmen kann.
18. WENN ein Teilnehmer einen gültigen Einmal-Link öffnet, über den die Umfrage noch nicht erfolgreich übermittelt wurde, DANN SOLL DAS System den Einmal-Link nicht als verbraucht kennzeichnen; DAS System SOLL einen Einmal-Link ausschließlich zusammen mit der erfolgreichen Speicherung der Antwort als verbraucht kennzeichnen.
19. DAS System SOLL eine gespeicherte Antwort ohne Verweis auf den Einmal-Token, den Kampagnen-Link oder die Teilnahmekennung speichern, über die sie abgegeben wurde, und keine Zeitangaben speichern, mit denen eine Antwort einem Einmal-Token oder einer Teilnahmekennung zugeordnet werden kann.

### Requirement 8: Umfrage beantworten

**User Story:** Als Teilnehmer möchte ich die Umfrage anonym beantworten, damit ich je Item einschätzen kann, wie stark der zugrunde liegende Wert im Daily Business gelebt wird, und optional einen Kommentar hinterlassen kann.

#### Acceptance Criteria

1. WENN ein Teilnehmer die Umfrage einer Kampagne erstmals öffnet, DANN SOLL DAS System eine zufällig aus den zu diesem Zeitpunkt nicht deaktivierten Items des Kampagnen-Pools gezogene Teilnehmer-Teilmenge im Umfang von genau der Item-Anzahl je Teilnehmer für diesen Teilnehmer ziehen und ausschließlich die Items dieser Teilnehmer-Teilmenge zur Bewertung anzeigen.
2. DAS System SOLL je Item der Teilnehmer-Teilmenge genau eine Ist-Bewertung über einen Schieberegler als stufenlosen Dezimalwert auf der Skala von 1,00 bis 5,00 (einschließlich 1,00 und 5,00, Zwischenwerte zulässig) erfassen, wobei der Schieberegler dem Teilnehmer als Grad der gelebten Zustimmung dargestellt wird und die Perspektive des Items als Kontext der Item-Formulierung dargestellt wird.
3. DAS System SOLL je Item der Teilnehmer-Teilmenge einen optionalen Freitextkommentar von 0 bis 1.000 Zeichen erfassen.
4. WENN ein Teilnehmer für ein Item der Teilnehmer-Teilmenge eine Ist-Bewertung übermittelt, die kleiner als 1,00 oder größer als 5,00 ist, DANN SOLL DAS System die Ist-Bewertung ablehnen, die bisher erfassten gültigen Bewertungen beibehalten und eine Fehlermeldung anzeigen, die das betroffene Item und den zulässigen Wertebereich von 1,00 bis 5,00 benennt.
5. WENN ein Teilnehmer die Umfrage übermittelt, ohne für jedes zum Zeitpunkt der Übermittlung noch nicht deaktivierte Item der Teilnehmer-Teilmenge eine Ist-Bewertung erfasst zu haben, DANN SOLL DAS System die Übermittlung ablehnen, die bereits erfassten Bewertungen und Freitextkommentare beibehalten und die Liste der noch nicht deaktivierten Items mit fehlender Ist-Bewertung anzeigen.
6. WENN ein Teilnehmer die Umfrage übermittelt und für jedes zum Zeitpunkt der Übermittlung noch nicht deaktivierte Item der Teilnehmer-Teilmenge eine gültige Ist-Bewertung im Bereich von 1,00 bis 5,00 vorliegt, DANN SOLL DAS System die Antwort einschließlich der optionalen Freitextkommentare dauerhaft speichern und innerhalb von 3 Sekunden eine Bestätigung anzeigen.
7. WENN ein Teilnehmer eine Ist-Bewertung für ein Item übermittelt, das nach der Zuweisung der Teilnehmer-Teilmenge in der Kampagne deaktiviert wurde, DANN SOLL DAS System diese Ist-Bewertung annehmen und speichern, sie aber nicht als erforderliche Bewertung behandeln und von der Berechnung des Ist-Scores ausschließen.
8. WENN ein Teilnehmer die Umfrage übermittelt und kein Item der Teilnehmer-Teilmenge mehr aktiv ist, DANN SOLL DAS System die Übermittlung ablehnen, keine Antwort speichern und den einheitlichen Hinweis anzeigen, dass die Umfrage derzeit nicht verfügbar ist.
9. DAS System SOLL jede gespeicherte Antwort einschließlich der Freitextkommentare ohne personenbezogene Identifikationsdaten des Teilnehmers (insbesondere ohne Name, E-Mail-Adresse, IP-Adresse oder Benutzerkennung) speichern.
10. WENN die Umfrage erfolgreich übermittelt und gespeichert wurde, DANN SOLL DAS System verhindern, dass über denselben Kampagnen-Link (Teilnahmekennung) oder denselben Einmal-Link ein weiteres Mal eine Antwort gespeichert wird, unabhängig davon, ob die Link-Kennung (Kampagnen-Link bzw. Teilnahmekennung oder Einmal-Link) bei der zweiten Übermittlung gültig oder vorhanden ist, sofern die zweite Übermittlung über denselben Link bzw. dieselbe Teilnahme erkannt wird.
11. WENN ein Teilnehmer die Umfrage über denselben Einmal-Link bzw. mit derselben Teilnahmekennung vor der erfolgreichen Übermittlung erneut öffnet, DANN SOLL DAS System dieselbe Teilnehmer-Teilmenge wie beim ersten Öffnen anzeigen und keine neue Teilnehmer-Teilmenge ziehen; Items, die inzwischen in der Kampagne deaktiviert wurden, SOLL DAS System dabei nicht mehr anzeigen und nicht durch andere Items ersetzen.
12. WENN beim erneuten Öffnen gemäß Kriterium 11 kein Item der Teilnehmer-Teilmenge mehr aktiv ist, DANN SOLL DAS System den Zugang ablehnen, den Einmal-Link unverbraucht lassen und den einheitlichen Hinweis anzeigen, dass die Umfrage derzeit nicht verfügbar ist.
13. WÄHREND ein Teilnehmer die Umfrage beantwortet, SOLL DAS System den Zwischenstand ausschließlich im Browser des Teilnehmers speichern, beim erneuten Öffnen im selben Browser wiederherstellen und vor der erfolgreichen Übermittlung keine Ist-Bewertungen oder Freitextkommentare auf dem Server speichern.
14. WENN die Umfrage erfolgreich übermittelt wurde, DANN SOLL DAS System den Zwischenstand im Browser des Teilnehmers löschen und die serverseitige Bindung der Teilnehmer-Teilmenge an den Einmal-Token bzw. die Teilnahmekennung entfernen.

### Requirement 9: Ist-Score berechnen

**User Story:** Als Administrator möchte ich je Unternehmenswert einen gewichteten Ist-Score berechnen lassen, damit ich erkenne, wie stark der Wert im Daily Business tatsächlich gelebt wird.

#### Acceptance Criteria

1. WENN das System die Ist-Scores einer Kampagne im Status "Aktiv" (Zwischenauswertung) oder "Abgeschlossen" (Endauswertung) berechnet, DANN SOLL DAS System je Item-Bewertung der einbezogenen Antworten den Beitrag zu einem Unternehmenswert und zur Perspektive des Items als Produkt aus der Gewichtung der Werte-Zuordnung des Items und der Ist-Bewertung des Teilnehmers berechnen und dabei ausschließlich Items einbeziehen, die Teilnehmer in ihrer Teilnehmer-Teilmenge tatsächlich gesehen und bewertet haben und die in der Kampagne nicht deaktiviert wurden.
2. WENN die Item-Beiträge eines Unternehmenswerts je Perspektive (Selbst, Team, Führung) berechnet sind, DANN SOLL DAS System den Ist-Score des Unternehmenswerts getrennt je Perspektive als Summe der Beiträge (Gewichtung je Item multipliziert mit der Ist-Bewertung) der Items dieser Perspektive geteilt durch die Summe der zugehörigen Gewichtungen berechnen und auf der Skala von 1,00 bis 5,00, gerundet auf zwei Nachkommastellen, ausdrücken.
3. WENN zu einem Unternehmenswert für eine Perspektive keine bewertete Item-Zuordnung dieser Perspektive mit einer Gewichtung größer als 0 % vorliegt, DANN SOLL DAS System diesen Unternehmenswert für diese Perspektive als "keine Daten" kennzeichnen und aus der Berechnung des zugehörigen Ist-Scores ausschließen; Ist-Bewertungen deaktivierter Items zählen dabei nicht als bewertete Item-Zuordnung.
4. WENN kein einbezogener Unternehmenswert für mindestens eine Perspektive mindestens eine beitragende Bewertung aufweist, DANN SOLL DAS System die Auswertung der Kampagne als "keine Daten" kennzeichnen und einen entsprechenden Hinweis bereitstellen.
5. DAS System SOLL die Ist-Bewertungen eines in der Kampagne deaktivierten Items gespeichert lassen, aber aus der Berechnung aller Ist-Scores dieser Kampagne ausschließen, und zwar unabhängig davon, ob die Ist-Bewertung vor oder nach der Deaktivierung abgegeben wurde.
6. DAS System SOLL je in der Kampagne deaktiviertem Item die Anzahl der aufgrund der Deaktivierung ausgeschlossenen Ist-Bewertungen als ganze Zahl ermitteln.
7. DAS System SOLL je Unternehmenswert und Perspektive zusätzlich zum Ist-Score die Anzahl der beitragenden Teilnehmer als ganze Zahl ermitteln.

### Requirement 10: Auswertung anzeigen

**User Story:** Als Administrator möchte ich die Auswertung einer laufenden oder abgeschlossenen Kampagne und die Entwicklung der Werte über mehrere Kampagnen einsehen, damit ich die Ergebnisse interpretieren und den Trend je Unternehmenswert erkennen kann, ohne dass einzelne Teilnehmer erkennbar werden.

#### Acceptance Criteria

1. WENN ein Administrator die Auswertung einer Kampagne im Status "Aktiv" oder "Abgeschlossen" öffnet und die Anonymitätsschwelle gemäß Kriterium 6 erreicht ist, DANN SOLL DAS System je Unternehmenswert die drei Ist-Scores der Perspektiven Selbst, Team und Führung, jeweils gerundet auf zwei Nachkommastellen, nebeneinander anzeigen, sodass die drei Sichten verglichen werden können, und je Perspektive die Anzahl der beitragenden Bewertungen als ganze Zahl anzeigen, wobei Bewertungen von in der Kampagne deaktivierten Items nicht mitgezählt werden.
2. WENN die Auswertung einer Kampagne angezeigt wird, DANN SOLL DAS System die Unternehmenswerte aufsteigend nach Ist-Score der Perspektive Selbst sortieren, bei gleichem Ist-Score alphabetisch aufsteigend nach Bezeichnung des Unternehmenswerts sortieren und Unternehmenswerte ohne angezeigten Ist-Score der Perspektive Selbst alphabetisch aufsteigend ans Ende stellen.
3. WENN ein Administrator die Auswertung einer Kampagne im Status "Aktiv" oder "Abgeschlossen" öffnet, DANN SOLL DAS System je Unternehmenswert die zugehörigen anonymen Freitextkommentare der einbezogenen Antworten anzeigen, mit Ausnahme der Freitextkommentare zu Items, die in der Kampagne deaktiviert wurden, und nur sofern für diesen Unternehmenswert die Anonymitätsschwelle gemäß Kriterium 14 erreicht ist.
4. WENN ein Administrator die Entwicklung eines Unternehmenswerts über mehrere Kampagnen öffnet, DANN SOLL DAS System den Verlauf des Ist-Scores dieses Unternehmenswerts je Perspektive (Selbst, Team, Führung) über die abgeschlossenen Kampagnen in chronologischer Reihenfolge anzeigen.
5. WENN der Ist-Score eines Unternehmenswerts für eine Perspektive gegenüber der vorherigen abgeschlossenen Kampagne steigt oder fällt, DANN SOLL DAS System die Richtung der Veränderung je Unternehmenswert und je Perspektive kennzeichnen.
6. WENN ein Administrator die Auswertung einer Kampagne mit mindestens einer, aber weniger abgegebenen Antworten als der Anonymitätsschwelle öffnet, DANN SOLL DAS System die Anzahl der abgegebenen Antworten und die Anonymitätsschwelle sowie einen Hinweis anzeigen, dass die Auswertung zum Schutz der Anonymität erst ab Erreichen der Schwelle verfügbar ist, und SOLL weder Ist-Scores noch Bewertungsanzahlen je Unternehmenswert noch Freitextkommentare anzeigen.
7. WENN ein Administrator die Auswertung einer Kampagne im Status "Entwurf" öffnet, DANN SOLL DAS System einen Hinweis anzeigen, dass noch keine Auswertung verfügbar ist, und SOLL keine Ist-Scores anzeigen.
8. WENN ein Administrator die Auswertung einer Kampagne mit null abgegebenen Antworten öffnet, DANN SOLL DAS System einen Hinweis anzeigen, dass keine Antworten vorliegen, und SOLL anstelle des Ist-Scores keine berechneten Zahlenwerte anzeigen.
9. WENN ein Administrator die Auswertung einer Kampagne mit null abgegebenen Antworten öffnet, DANN SOLL DAS System den Abschnitt der Freitextkommentare ebenso wie die Ist-Scores vollständig durch den Hinweis "keine Antworten" aus Kriterium 8 ersetzen und nicht anzeigen.
10. WENN ein Administrator die Auswertung einer Kampagne öffnet, in der mindestens ein Item deaktiviert wurde, DANN SOLL DAS System je deaktiviertem Item den Item-Text, den Zeitpunkt der Deaktivierung und die Anzahl der aufgrund der Deaktivierung von der Auswertung ausgeschlossenen Ist-Bewertungen als ganze Zahl anzeigen.
11. WENN in einer Kampagne kein Item deaktiviert wurde und ein Administrator die Auswertung öffnet, DANN SOLL DAS System einen Hinweis anzeigen, dass keine Items deaktiviert wurden.
12. WENN ein Administrator die Auswertung einer Kampagne im Status "Aktiv" öffnet, DANN SOLL DAS System die Auswertung als vorläufige Zwischenauswertung kennzeichnen, ausschließlich die ersten m abgegebenen Antworten einbeziehen (m = größtes ganzzahliges Vielfaches der Anonymitätsschwelle, das die Anzahl abgegebener Antworten nicht übersteigt) und die Anzahl der einbezogenen sowie der insgesamt abgegebenen Antworten anzeigen.
13. WENN zu einem Unternehmenswert in einer Perspektive die Anzahl der beitragenden Teilnehmer der einbezogenen Antworten kleiner als die Anonymitätsschwelle ist, DANN SOLL DAS System für diesen Unternehmenswert und diese Perspektive anstelle des Ist-Scores und der Bewertungsanzahl einen Hinweis "zu wenige Antworten" anzeigen.
14. WENN zu einem Unternehmenswert die Anzahl der Teilnehmer, die für mindestens eine Perspektive dieses Unternehmenswerts beitragende Teilnehmer sind, kleiner als die Anonymitätsschwelle ist, DANN SOLL DAS System die Freitextkommentare dieses Unternehmenswerts nicht anzeigen und stattdessen einen Hinweis "zu wenige Antworten" anzeigen.
15. WENN der Verlauf eines Unternehmenswerts angezeigt wird, DANN SOLL DAS System ausschließlich abgeschlossene Kampagnen einbeziehen und für eine Kampagne, in der für eine Perspektive die Anonymitätsschwelle gemäß Kriterium 13 nicht erreicht ist, für diese Perspektive keinen Wert, sondern eine Lücke anzeigen; die Richtungskennzeichnung gemäß Kriterium 5 bezieht sich dann auf die letzte vorherige abgeschlossene Kampagne mit angezeigtem Wert.

### Requirement 11: Auswertung exportieren

**User Story:** Als Administrator möchte ich die Auswertung exportieren, damit ich die Ergebnisse außerhalb der Applikation weiterverwenden kann.

#### Acceptance Criteria

1. WENN ein Administrator den Export einer abgeschlossenen Kampagne auslöst, DANN SOLL DAS System innerhalb von 10 Sekunden eine CSV-Datei erzeugen, die je Unternehmenswert eine Zeile mit den drei Ist-Scores der Perspektiven Selbst, Team und Führung, jeweils gerundet auf zwei Nachkommastellen, und der Anzahl der beitragenden Bewertungen je Perspektive enthält.
2. WENN die CSV-Datei erzeugt wird, DANN SOLL DAS System in der ersten Zeile eine Kopfzeile mit den Spaltenbezeichnungen für Unternehmenswert, Ist-Score Selbst, Ist-Score Team, Ist-Score Führung sowie die Anzahl der Bewertungen je Perspektive ausgeben.
3. WHERE ein Administrator den Export der Freitextkommentare anfordert, SOLL DAS System die anonymen Freitextkommentare je Unternehmenswert zusätzlich in die CSV-Datei aufnehmen.
4. WENN ein Administrator den Export einer Kampagne auslöst, die sich nicht im Status "Abgeschlossen" befindet, DANN SOLL DAS System den Export ablehnen, keine Datei erzeugen und eine Fehlermeldung anzeigen, die angibt, dass nur abgeschlossene Kampagnen exportiert werden können.
5. WENN eine abgeschlossene Kampagne für einen Unternehmenswert in einer Perspektive keine beitragende Bewertung enthält, DANN SOLL DAS System für diese Perspektive dieses Unternehmenswerts den Ist-Score als leeres Feld ausgeben und die übrigen Felder der Zeile vollständig erzeugen.
6. WENN eine abgeschlossene Kampagne Items enthält, die während der Kampagne deaktiviert wurden, DANN SOLL DAS System die Ist-Bewertungen und Freitextkommentare dieser Items weder in die Ist-Scores noch in die Anzahl der beitragenden Bewertungen noch in die exportierten Freitextkommentare der CSV-Datei aufnehmen.
7. WENN ein Administrator den Export einer abgeschlossenen Kampagne mit weniger abgegebenen Antworten als der Anonymitätsschwelle auslöst, DANN SOLL DAS System den Export ablehnen, keine Datei erzeugen und eine Fehlermeldung anzeigen, die auf die nicht erreichte Anonymitätsschwelle hinweist.
8. WENN die CSV-Datei erzeugt wird, DANN SOLL DAS System für jeden Unternehmenswert und jede Perspektive, für die die Anonymitätsschwelle gemäß Anforderung 10.13 nicht erreicht ist, den Ist-Score und die Anzahl der Bewertungen als leere Felder ausgeben und Freitextkommentare von Unternehmenswerten, für die die Anonymitätsschwelle gemäß Anforderung 10.14 nicht erreicht ist, nicht aufnehmen.
